# ADR-0001: 采用 Spring Boot 模块化单体（Modular Monolith）架构

## 状态
已接受 (Accepted)

## 上下文
CCDDesigner 2.0 面向复杂数控机床正向设计，涵盖 30 个功能模块，业务涉及系统模型发布、多级装配 BOM、参数 DAG 计算、工程变更与数字主线追踪。在系统研制初期（P0/P1 阶段），SysML 模型发布与基线冻结涉及频繁的跨模块强一致性事务（如 M04/M06/M19/M24 两阶段提交）。如果过早拆分为微服务集群，将导致大量分布式事务、跨服务网络调用及高昂的运维编排成本。

## 决策
在 P0 至 P1 阶段，PLM 核心服务采用 **Spring Boot 模块化单体（Modular Monolith）** 架构模式进行开发与部署：
1. **单一代码库与单一部署单元**：核心业务逻辑在一个工程内按业务域清晰划分为独立 Maven/Gradle Module（或 Java package），共享同一个 PostgreSQL 实例。
2. **强制模块边界隔离**：模块间调用通过严谨的应用服务接口（Application Service Interface）与领域事件，严禁跨模块直接注入底表 Repository 或绕过主责模块写库。
3. **进程内事务保证一致性**：核心发布流程利用本地关系数据库事务保证 ACID，降低分布式事务复杂度。
4. **外部重型工具独立解耦**：SysON/OpenSysML 编辑器、Flexo RDF 存储、OpenModelica 仿真计算池依然作为独立服务/容器外部部署。
5. **演进路径**：当进入 P2/P3 且各模块业务边界稳定、团队规模扩大后，具备清晰依赖边界的模块可平滑解耦为独立微服务。

## 影响
- **正面**：开发与调试链路短，重构成本低，两阶段模型发布与基线冻结可利用本地数据库事务确保原子性。
- **负面**：各模块需严格遵循模块包访问控制规范，防止代码腐化产生不合规的跨模块隐式耦合。
