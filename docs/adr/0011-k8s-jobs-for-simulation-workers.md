# ADR-0011: 采用 Kubernetes Job 容器化调度 OpenModelica 仿真计算

## 状态
已接受 (Accepted)

## 上下文
CCDDesigner 2.0 中 M10（仿真调度与结果管理）负责调用 OpenModelica 求解容器执行数控机床动态力学、热平衡及伺服跟随特性仿真。仿真计算任务具有以下特征：
- 突发性与高 CPU/内存消耗；
- 脚本可能由于不收敛而发生死循环或引发求解器段错误（Segmentation Fault）；
- 核心要求严格保证计算结果的可复现性（AT-06 用例要求提取历史 Run 的离线复现包可独立重跑且 KPI 误差在容差内），需要求解器底层依赖与版本绝对冻结。

## 决策
采用 **Kubernetes Job 动态生命周期容器调度** 架构：
1. **动态隔离运行**：每次发起仿真执行尝试（`SimulationRun`）时，M10 调度器通过 Kubernetes API 动态下发一个独立的 Job Pod。
2. **环境版本强绑定**：仿真任务严格绑定特定标签且带有 SHA-256 摘要的 Docker 镜像（如 `openmodelica:1.22.0-omc`），严禁使用 `:latest`。
3. **安全与资源约束**：容器强制配置 CPU/内存 `limits` 与 `activeDeadlineSeconds` 硬超时熔断机制；禁止容器拥有高特权（`privileged: false`）。
4. **产物落盘与回调解耦**：计算产物、求解曲线与日志由容器生命周期钩子或 Sidecar 直接上传至 MinIO，并向 M10 异步回调状态；M10 通过心跳与超时探测处理 Worker 状态。

## 影响
- **正面**：计算环境物理隔离，单次求解崩溃不会波及 PLM 核心；版本可追溯、可审计；天然支持按需弹性扩缩容。
- **负面**：冷启动时拉取镜像或拉起 Pod 相较于常驻线程池有秒级开销（约 2~3 秒），但对分钟级的物理工程仿真而言完全可接受。
